## P 力石装卸修复

背包石原回包包含 `pos=0`，而原 `spgem_view` 使用 `item.data.pos or 自动槽位`。Lua 中 0 为真，导致自动选择的第一开放槽被覆盖为第 0 槽，C251 返回参数错误。现仅已穿戴石发送有效 pos，背包石省略该字段。原 Lua 实跑对比：修改前选槽 0，修改后选槽 1。

卸下成功原回包包含 `stoneid=""`，同样被 Lua 当成穿戴分支。现卸下省略 stoneid，穿戴保留实际实例编号。原回调实跑确认卸下返包一次；实际安装后的 C251 全分派验证穿脱成功且卸下字段确实省略。

实际 Unity 界面回归通过：截图同一玩家的 120 级小软，点击 8 级快快石穿戴成功，第一槽显示石头、背包 4→3；点击已装石卸下成功，第一槽恢复空槽、背包 3→4，无参数错误，也未重复返包。回归结束已卸下，恢复玩家原有装备状态。

## P 力石属性加成分析

**已确认本地战斗与战力未读取 P 力石 extra，因此实际加成尚未生效；本次未将这项验证分析扩展为属性计算机制重写。** 装卸记录成功不能等同于属性生效。

安装进程内创建独立验收角色，通过真实业务装上与卸下力石，再从数据库重新读取精灵并调用实际 `BattleService.player` 与 `RoleBattlePowerService.elfScore`。六维属性、次级属性及战力均无变化。样例物攻 37483、生命 39060、速度 14351、战力 18759800，穿戴前后相同。冷进程恢复也得到相同结果。客户端界面自行计算的战力在实际穿戴时由 851059 升到 958942，卸下恢复 851059；因此本结论特指本地 Java 战斗快照及 RoleBattlePowerService，不能说客户端显示也无变化。

原模板只有词条属性，无另一组固定主属性；180 的百分比词条代表 18%。原双架构配置全量审计通过 108 模板、96 合成路线、1035 词条引用。详见数值目录的《P力石装卸属性与合成分解核验_20261122.md》。实际 Unity 详情已能显示物攻 +60000、草系技能免伤 +57%、速度加成 +18%；原始显示函数字段差异未在当前页面复现。
