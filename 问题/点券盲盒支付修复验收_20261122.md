# 点券商城与盲盒支付修复及验收

日期：2026-11-22（北京时间）。本地工作区修改，未提交或推送。

## 点券商城报错

固定底包 chongzhi_proto 的 1001—1010 共十档商品缺失于本地目录，因此下单返回“该游戏商品尚未配置本地发放”。现按原表 chargeValue/voucher 接入 600、2000、3280、6800、9800、19800、32800、64800、100000、200000 十档，1008—1010 首次购买额外赠送等额永久券。Android 支付入口接受以券为奖励的有效订单。确认与发券沿用同一 SQLite 事务、订单确认去重，未改变原档位数量、价格或概率。

购买点券本身不计入 VIP/活动充值；使用代金券购买原商品时才累计，对应累计充值视图排除 1001—1010。首购状态仍以真实已确认订单判定。

## 盲盒现金按钮无效

原 SDK 的 order 第二参数表示跳过支付方式选择。原现金按钮实际调用 order(sid,true)，离线 Lua 却将 true 解释为允许弹窗，再次打开选择窗口后返回。现更正为 skipVoucher，现金选择直接下单，不再循环弹窗；代金券按钮继续走原 recharge_with_voucher 与同一套订单结算。

原六档盲盒 401/402/407/403/404/405 保留原价格、库存行和奖励池。已下架活动商品 301、303—306、501/503/504 不接受新的现金或代金券订单；既有确认路径及已结算券凭据重放保留。

## 实际验证

- 追加真实字节码执行：从固定底包64位manager提取sdk_mgr，经最终patch_calls(order)修补后在64位LuaJIT运行；同时运行底包原rechagepopup.on_rmb。六档默认各显示一次方式选择，六次真实现金回调携带true进入原sdk.purchase，不再回弹；十档点券默认无方式选择直接下单，合计16次API下单及原SDK Purchase调用。SDKAdapter、资源/UI、JSON编码及进程内API使用依赖替身，未将其描述为Unity实机点击。字节码摘要见机器记录。
- 64 位 LuaJIT 隔离执行新离线下单源码：六档首次弹出方式选择，现金回调 true 进入六次下单；十档点券现金均可下单。原弹窗字节码反汇编确认现金按钮第二参为 true。
- MuMu 专用 QA 实例 16416，使用无服务端的隔离编译业务 DEX，真实 Android SQLite：十档点券各购买两次，每笔确认重放不重复发券；最后三档首购双倍、再购单倍。
- 六档盲盒分别现金模拟支付、代金券支付并重放凭据，各库存行恰为两包，32 笔已确认订单。付款后永久券精确为 1241120。
- 调用真实 Feature.tick 可生成 S464、S3 钱包及 32 条 S11，直接调用在五秒内完成。强停重开业务后，券余额、六行箱子和 32 笔订单保留。
- 在 QA SQLite 应用更新后的原始 CREATE VIEW，累计金额精确为 688000 分：仅计现金及代金券消费的盲盒订单，购券不计。
- Java/DEX 独立编译由主任务执行。最后的下架券单统一守卫和累计充值视图晚于设备 DEX 快照，主任务最终 Java/DEX 已重新编译纳入（DEX 摘要前缀222dd789）；这些项未在前述设备 DEX 上执行，最终APK仍以主任务打包核验为准。
