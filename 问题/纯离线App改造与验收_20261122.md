## 实现结果

- 默认规则写入 [AGENTS.md](../AGENTS.md)：未明确说明时，所有实现均归 App 本地离线代码，不使用服务端模块、PC 服务、HTTP/TCP 监听或 ADB 反向转发。
- App 自有业务、SQLite 适配、组件装配及协议代码位于 `app端代码/local-patch/offline/src/com/pokemon/offline/`，配置和 SQL 位于 `offline/resources/`。原 Spring/SLF4J 外观包迁为 App 自有 platform，不引入 Spring 或 H2 运行时。
- 前轮对服务端的 v4 修改已迁入 App，服务端目录恢复分支基线内容；迁移前的副本留在忽略的 `.tools` 目录，交付快照未修改。
- Unity 游戏帧保持原 sproto 编解码及会话，通过 FFI → 双 ABI JNI → OfflineBridge.exchange → App 离线会话直接处理。App 内计时器生成已提交推送，Unity 直接提取，不监听端口。区服、角色历史和原 WWW 下单路径也改为直接调用。
- APK metadata 固化 `file:///sdcard/Android/data/<包名>/files/offline-bootstrap`，App 将小配置写入自身外部私有目录，配置指向内部已校验的完整资源。metadata 字面量追加在末尾，其他表偏移不移动；缓存与安装包保持相同字节及长度，避免被 Unity 重新覆盖成错误入口。
- Android 工作台和游戏支付桥校验本地订单后直接结算，不再显示二次确认框。工作台先保存客户端订单号，游戏侧只采用本地订单中记录的商品、价格及奖励；同单幂等约束与事务保留。
- 使用用户提供的 fate 目录作为本地存档与启动参考。该目录实际仍监听 HTTP 且构建引用服务端，未照搬这些与本次明确要求冲突的部分。

## 设备实测

使用既有专用 MuMu 验收实例1，安装独立包名 `com.qk.offline.pokemon.qa` 的副本，避免覆盖原包和玩家数据。QA 副本只调整包名、资源命名空间、metadata入口及debug标志；业务DEX、JNI、玩法资源和最终构建一致。最初只改包名引发的资源命名空间错误已在QA副本中修正，最终主包沿用原包名不受影响。

- Wi-Fi和移动数据均为关闭状态，ADB reverse为空；8081/9003没有监听。
- 本地登录admin成功，私有SQLite初始化完成。
- 工作台点击一次模拟充值，未弹二次确认框，余额从0到60；数据库确认仅一笔已结算订单。
- 修正metadata入口后，Unity ARMv7读取文件配置和本地区服，成功SDK登录、进服建角并加载主场景；本地数据库有1个角色、1只精灵。
- 强停App后重新启动、登录并进入Unity，角色与精灵记录、余额60及1笔订单保留，主场景可重新加载。
- QA生成的完整文件资源约455 MB，均在私有目录；原玩家目录未修改。

实际日志存在原Unity ThreadManager终止线程时的ThreadAbortException，运行继续；未宣称无任何异常日志。完整初始引导、游戏内SDK购买及同单重复回调、盲盒五秒到账、洗炼重登、战斗和ARM64设备仍待专项回归。本轮不把原已披露的速度努力石、领奖名字长度、特性真实数值空表及未迁移协议描述为已修复。
