## Java 对接字段与取整

1. 槽位必须已解锁、有本角色持有的合法精灵实例，且不能和本场出战 UID 重复。原 `compute_power` 只核对 cheer 表存在该槽；不能把它当作数据库解锁校验。
2. 品质取原物种 `jingling_proto.quality`。等级取精灵 `level`。个体总和为 `individual` 各维原值之和；原 `sprite_utils.sum_unit({100,200})` 返回 300，不除 10。星级取 `star`，原 Lua 觉醒字段为 `awakelv`，当前 Java 存档对应 `training.awakenlv`。
3. 累加达标条件的 `num1..num6` 得到 `percent`。
4. 原 `gaid_model.compute_add` 用 `ghelper.createteam({elf}, nil, 'flag')` 取得助战精灵的独立成品基础属性，再读取本槽指定属性。`flag` 用于计算自身基数，不能把其他助战的槽位或特性加成反灌进来源基数。
5. **逐槽贡献 = floor(来源属性 × percent / 100)**。原函数实测第一槽满条件、来源生命 10003，返回属性代码 5、贡献 2000。每槽先取整，再按同属性相加；不要先合并小数再取整。
6. 槽位贡献只加入本场原出战数组，不加入后排来源数组。助战特性同样只筛选原出战目标。来源自身属性不因队友助战变化，避免交叉放大或递归计算。

## UI 文案差异

用户截图文字提到个体 5000、15 星；但当前 002/004 相同的实际执行配置在首组六槽读取 `individual >= 500`、`star >= 5`。本产物如实保存执行表和执行字段，没有根据文字另改数值。实现应保留这一差异供后续文案/单位专项核对，不将显示文字反推为新阈值。
