# 称号时装百分比单位与安装验收

版本 `cosmetic-percentage-units-20261122-v1`。本文件补充并修正本次目录合并的属性单位说明。目录去重、源字段原值和加成总数不变；修正的是运行层把外观原千分值重复乘 10 的旧换算。

## 原包取证与结论

已经从固定 `origin.apk` 直接解密提取并逐字节核对以下证据，文件哈希见 `cosmetic-percentage-unit-evidence-20261122.json`：

- `lua64_database_attribute_proto.lua.bytes`：20、22、23、24–29、34–50、59–62、71–90 均为 `type=2`；5–14 和 63 为 `type=1`。
- `lua64_module_dress.ab / dress_view.lua.bytes`，原型18第111–127条：属性 `type=2` 时显示 `num / 10` 并追加 `%`，不是直接显示 `num%`。
- `lua64_helper.ab / ghelper.lua.bytes`，`get_att_str1/get_att_str2`（原型21、23）：称号属性同样为 `type=2` 时 `val / 10` 后追加 `%`。
- `lua64_module_battle.ab / stage.lua.bytes`，`handle_damage` 原型35：第227–236条读取 `damage_bonus - reduced`，除以常数1000后加1；物理／特攻增减伤、暴伤、元素增伤／全系技能免伤同样以1000为分母。

因此外观表的 `type=2` 原值本身就是战斗千分值：`raw=20` 为 `20‰=2%`，战斗字段应追加20，不应追加200。界面的百分比数为 `raw / 10`，比例数为 `raw / 1000`。

`type=1` 保留原点数。其中63是“精灵SP上限”，原战斗编队的技能点上限为 `100 + add_skill_point_limit`；新增35表示增加35点，不是35%也不是35‰。10–13原命中、闪避、暴击、韧性按原点数进入战斗公式，不在外观层额外变换。

## 基础六维的正确公式

`final = Math.round((base + flat) × (1000 + relative) / 1000)`。

- `base` 是当前精灵已经计算完培养和装备等前置规则、但尚未应用本次外观加成的属性。
- `flat` 为所有已拥有称号的 `own` 加上所有已拥有时装 `property` 的对应固定值。
- `relative` 为同一目录持有属性累计的对应千分值：生命24、速度25、物攻26、物防27、特攻28、特防29。
- 同一来源只加一次；原有和新增的百分比先相加，不对新增每件逐件乘倍率。穿戴和显示变化不再次累计持有加成。

例如固定 `base=1000` 的物攻：旧目录正确值 `round((1000+18410)×1.765)=34259`；只新增称号为35361；只新增时装为36759；二者全部新增为37907。此为单位演算夹具，设备实际值应把该角色同一快照的真实 `base` 代入，不能要求所有角色都等于此示例。

## 次级字段与旧换算纠错

检查时原 `RoleCosmeticService.BattleBonuses.apply` 对以下外观原值错误地乘10：

| 外观原属性代码 | 协议字段或字段组 | 正确转换 |
| --- | --- | --- |
| 20 | reduced | +raw |
| 22 | crit_damage_bonus | +raw |
| 23 | damage_bonus | +raw |
| 34–41、43–50 | 八种元素增伤／减伤 | +raw |
| 42 | skill_damage_reduced | +raw |
| 59、60 | physical_damage_bonus、special_damage_bonus | +raw |
| 61、62 | physical_damage_reduced、special_damage_reduced | +raw |
| 71–90 | 十种其他元素增伤／减伤 | +raw |

24–29在基础六维公式中已经按千分值正确使用，不应改变。10–13、63已经直接使用点数，也不应乘除10。

原 `stage.handle_damage` 中总伤害因子为 `clamp(1 + (damage_bonus - reduced) / 1000, 0.1, 10)`；技能属性因子包含 `1 + (对应元素增伤 - skill_damage_reduced - 对应元素减伤) / 1000`，也按原上下限钳制。暴伤及物理／特殊增减伤是各自分支，不能只修总增伤23而漏掉其他组。

此纠错会使旧目录对应字段的数值从例如旧错误伤害加成3700降为原值370。这不是删减玩家持有的称号或时装，而是修正重复乘10。设备比较必须分别使用“旧目录＋正确单位”“新目录＋正确单位”，不能把修正前旧包的错误倍率作为目录增量基线。

其他来源须独立区分：道馆驻防配置的伤害数值确实以“百分数”定义，将该配置乘10转换为战斗千分值仍然正确；家园雕像和装备也应沿各自来源字段的单位，不因外观原表修正而统一删除所有乘10。此次证据与修正范围限定为称号 `own`、时装 `property` 的原表单位。

## 安装后专项验收

1. 在相同存档、同一精灵、同样装备／队伍／驻防条件下，分别冻结旧目录、仅新增称号、仅新增时装、全目录四份战斗快照。读取快照实际字段，不以目录数量或UI拥有标记替代属性验收。
2. 六维应按上式使用真实 `base` 复算，分别核对新增称号百分比与新增时装百分比。称号目录为142项、时装目录为142项（保留原生重复ID）仅为覆盖检查，不等于属性已经生效。
3. 对新增时装，实际战斗字段相对“旧目录＋正确单位”应增加 `damage_bonus=140`、`skill_damage_reduced=210`、`add_skill_point_limit=35`，不是1400、2100、350。同一静态技能和相同对手条件下复算伤害因子，确认消费端使用这些字段。
4. 直接检查10–13不被误缩放，63确为SP固定点数；并用合成的单字段夹具覆盖20、22、23、34–50、59–62、71–90，避免本次新增未涉及的属性码仍留旧×10错误。
5. 新账号、旧档升级、退出重进及重启后均应得到同一目录派生加成；穿脱时装、佩戴／隐藏称号不再重复增加。对重复请求或重复迁移也不累计永久基础属性。
6. 代码检查表明 `BattleService.player` 与 `ArenaCombat.player` 均调用 `bonuses.apply`；原Unity `stage.handle_damage` 和 App `ArenaCombat.trainingDamage` 使用对应千分字段。历史 `arenaDamageVersion=0` 的旧简化伤害分支不等于当前训练伤害分支，若测试落入旧存档战斗回放应单列，不能混作当前新开战斗的通过结果。

## 混合属性贡献源的单位复核

`BattleBonuses.attributes` 不仅含外观。本次同时核对现行其他贡献源，确认它们进入同一字典时均保持原属性单位：固定代码是点数，type2代码是千分整数。

| 贡献源 | 运行字段／代码 | 确证 |
| --- | --- | --- |
| 石板 `guild/tablet-attributes.json` | 600级全部键仅5、6、7、8、9、14 | 只有固定六维点数，无type2倍率，不受去掉次级字段×10影响 |
| 装备洗炼 `gear-refine.json` | 全部词条池属性码仅5、6、7、8、9、14 | `addRefinementBonuses`把存储原值直接合并，单位为固定点数 |
| 装备强化 | 每级对5、6、7、8、9、14各加1 | `addEnhanceBonuses`只有固定值，无百分单位 |
| 装备进阶 `gear-advance.json` | 所有`cfg[3]`仅固定六维代码；`cfg[5]`、`cfg[6..8]`为增幅千分比 | `addAdvanceBonuses`用原属性值×增幅÷1000，结果仍是对应属性原单位；其已有÷1000保留，不新增×10 |
| 刻印 `trainer-runes.json.sets` | 原`suit.num1..tips`二元组 | 已从固定origin直接提取32/64位`suit_proto`逐值一致，106套运行sets逐项等于原表，未转为百分数 |

刻印界面 `suit_cover.lua` 原型3第21–27条进一步确认：`attribute.type==2` 时把`num[2]/10`追加`%`。例如10082首档`[61,50]`是5%物攻伤害减免，正确协议字段增加50；旧实现增加500属于同一旧十倍错误，不是需要保留的额外业务单位。

只有道馆驻防这一已知配置入口使用明确百分数，在汇总之前将其乘10变为raw千分值应继续保留。家园雕像在独立`statues`字典中，不经过本次原表纠错路径。现行上述洗炼、进阶、强化、刻印、石板四类贡献没有发现尚需在源端补乘10的业务百分数。
