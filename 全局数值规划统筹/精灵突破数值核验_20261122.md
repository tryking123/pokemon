# 精灵突破数值核验

- 核验日期：2026-11-22（北京时间）。
- 适用：C270 注入、C271 突破，`training.veinlevel`；当前离线业务源码及固定原 APK。
- 本次只核验，未调整奖励、消耗、概率或业务代码；设备业务回归由主任务记录。

## 结论

修复前确认原配置导出和 App 属性应用存在缺口：`elf/training.json` 的 132 条 break 配置全部缺少原表 `attributes`，另缺 variable3810–3821 的基础成长系数；原 `ElfCombatGrowth.attribute/powerAttribute/apply` 不读取这些突破加成，只在开战对象中写出 `vein=veinlevel`。本次数值负责人已恢复两组原配置，Java修复和设备验收由主任务单独记录。不能仅根据Unity原表仍有属性就认定实际成品快照已正确：须区分原elfinfo重算链和Java发pokemon_t成品后直接Formation/Stage.load链，后者不应依赖再次调用原init来补算。

另有亲密度上限缺口：原 `elf_handle.lua` proto2 以 `variable[2501].data6[quality] + break[veinlevel].extra` 计算 maxlove；Java `ElfTrainingService.advanceIntimacy` 只读品质基础上限，遗漏突破 extra。`extra` 不是六维百分比，禁止直接按 extra/100 或 extra/1000增加所有属性。努力值上限 `strive` 在 Java 普通训练及努力值棋盘入口已有读取。

## 完整基础成长与字段单位

继续追踪原 `core/init.lua` 的 `new` 闭包 upvalue6（原指令未改），绑定原variable表实跑得到：stage=floor(veinlevel/11)，stage为0时成长系数0；否则基础成长加成读取 `variable[3809+stage].data1`。原3810–3821依序为0.2、0.4、0.6、0.8、1、1.2、1.4、1.6、1.8、2、2.2、2.4，第二返回stage写入战斗成品 `vein`。

原proto28第227–229调用该辅助函数，第261把第二返回值写`vein`；第475–482调用proto16把另一套attributes加入属性池；第530–565以`(1000+对应bonus)/1000`放大六维。故`veinlevel`（进度0–132）、`vein`（阶级0–12）、`damage_lv`（伤害等级0–20）三者不能混用。

完整顺序是：基础成长系数与原星级/觉醒系数同池；再乘属性池中的突破六维千分比。纯示例base1000且无其他来源时，11档生命为1000×1.2×1.06=1272，而不是1000×1.26=1260。其他属性及角色来源仍须按原各自加成池汇总，不能无条件连乘所有来源。

证据 [精灵突破阶级原计算证据_20261122.json](精灵突破阶级原计算证据_20261122.json) 包含0–132全部原辅助闭包输出；[精灵突破原计算证据_20261122.json](精灵突破原计算证据_20261122.json) 的samples为全部132档原属性池，stageSamples为基础系数和阶级。
