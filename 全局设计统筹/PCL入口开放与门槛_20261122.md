# PCL 入口开放修复方案

日期：2026-11-22（北京时间）。适用接口：C417–C420。本文仅澄清既有入口开放条件，不新增养成规则或奖励。

## 问题与来源

原 APK 的 `lua32_database_leading_proto.lua.bytes`、`lua64_database_leading_proto.lua.bytes` 中，1195 号 PCL 记录为 `study=0,name=2182,gatelevel=80,door=0`。

原 `module_sprite/sphandle_view.lua` 点击 PCL 时调用 `chr_model.unlock(1195,true)`。原 `gmodel/chr_model.lua` 的 `unlock`（原型45）先在启用提示且 `door==0` 时显示通用未开放提示并返回失败，再校验角色等级。因此达到80级后仍被关闭标记挡住。界面创建时调用不带提示参数的 `chr_model.unlock(1195)`，只检查等级，解释了按钮可见但点击报未开放的现象。

## 实施规则

1. 只将双架构 `leading_proto[1195].door` 从0改为1，保留80级门槛、名称及其余字段，保持其他功能开放配置不变。
2. 继续打开原 `pcl` 模块，调用已有 App 离线 C417–C420，不增加网络服务。
3. 原 `pcl_model.lua` 的 `get_pkm_list`（原型1）以 `jingling_proto[elf.sid].quality>=5` 筛选精灵，保持该限制。当前详情精灵符合品质时优先选中；当前详情精灵不符合且持有其他合格精灵时，回退选择排序后首个合格精灵，可在原列表切换。不要因为当前详情精灵品质低而阻止进入整个研究列表。
4. 没有合格精灵时，保留原空列表状态。原 `modules_pcl.ab` 的 `Empty` 节点已经显示“红色及红色以上的精灵才可开启实验”，无需重复添加提示。该节点 GameObject 的 pathId 为 `4920036636820149905`，对应 Text 组件 pathId 为 `2075090131343986755`；PCL视图原型21负责按列表是否为空显示此节点。
5. 不降低等级或品质要求，不赠送研究材料，不修改注入、升级、共鸣、重置、退款数值。

业务层依据：`app端代码/local-patch/offline/src/com/pokemon/offline/elf/PclResearchService.java` 第52–65行仍统一校验角色等级、实例归属和模板品质。设计入口参见 [App本地玩法设计与对接](App本地玩法设计与对接.md) 的“2026-11-19 精灵 PCL 研究 C417–C420”；路由参见 `interface-design-routes.json` 的 C417–C420 条目。

## 验收条件

| 场景 | 预期 |
| --- | --- |
| 训练家79级 | 原等级门槛继续生效，直接调用业务接口也不能激活 |
| 训练家80级，选中品质5或以上精灵 | PCL按钮可进入原研究页，不再提示功能未开放 |
| 训练家80级，当前精灵品质不足但持有其他合格精灵 | 进入研究页并选中合格精灵，低品质精灵不进入可研究列表 |
| 训练家80级，没有合格精灵 | 展示原空列表及“红色及红色以上的精灵才可开启实验”，不产生可激活的低品质实例 |
| 已研究精灵、重新进入或重启 | 已有方向、等级、注入量和共鸣正常显示，不重置存档 |
| 激活、注入、升级、重置 | 沿用已有离线协议和事务规则；材料不足或未注满仍被拒绝 |
| 32位与64位资源 | 只有1195号记录的door改变，双架构解析及原入口调用通过 |

## 校验状态与生效条件

已静态核对原APK的1195号记录、原点击及显示路径、品质筛选和空列表逻辑，以及当前 App 离线服务门槛。尚未以本文结论执行设备验收；生效以主智能体完成双架构资源补丁、独立 App 构建与包内校验后的APK为准。2026-11-19历史PC协议记录不能替代当前纯离线设备验证。

后续实施已完成：`pokemon-offline-20261122-pcl-open.apk` 已独立构建、校验并安装，双架构开放配置均仅修改1195号door。64位原入口字节码执行通过79级拒绝、80级打开，以及品质筛选、低品质回退与空列表；安装后的业务升级、战斗快照五方向增量、重置还原及冷进程读取也通过。具体数据与验证边界见 [PCL入口与安装属性验证](../问题/PCL入口与安装属性验证_20261122.md)。本段为前述静态方案的后续结果，未将原Lua执行及安装包业务验证等同于全部Unity界面和动态被动实战验收。
