# 自动闯关地图解锁核查

日期：2026-11-23（北京时间）。适用：App 纯离线 C3042 `fast_hangup`、S1007 `hangup`、原地图信息页。版本：jump-map-20261123-v2；来源为用户物理机反馈、截图、当前本地 Java 代码、最终 APK 提取的双架构 Lua，以及固定底包的双架构 `map_proto`、`copy_proto`、`fly_proto`。实现与设备结果以主智能体验证记录为准。

## 已核实的协议语义

- `AdventureProgressService.nextMission` 保存下一待挑战关卡，新角色为 10001；已通关数为 `nextMission - 10001`。地图页显示的当前关卡为 `mission - 10000`，不能将显示数字直接存入内部进度。
- C3042 返回 `start/final` 内部关卡编号，实际逐关执行 `clearAdventure`，进度与掉落按原事务提交；不能仅修改 Unity 显示或随意推进角色阶段修复解锁。
- 原 `allmaps_view` 解锁闭包使用 `hangup.mission - 1 >= map_proto.needlevel`，即完成门槛关后解锁。锁定图采用 `Common/common217` 图标和“未知区域”名称。入口、地图显示、传送许可和重新登录后的持久化进度应一致。
- 原地图43的进入门槛为内部16370，地图44为17310，45为18250；对应截图通关6370、7310、8250门槛。截图当前关卡6662时，6370图已显示、7310及之后锁定，单凭该截图不能判定这些锁图异常。
- `HangupMap.requiredWorld` 是原 `map_proto` 的训练师阶段条件；在尚无矛盾证据前保持原条件，不因自动闯关反馈移除或自动提高训练师阶段。

## 修复与验收边界

1. 在物理机核对已安装版本、App 私有 SQLite 下一关与 Unity `gnavi_model.get_hangup_data().mission`。复现一次跨地图门槛的自动闯关，检查 C3042 返回、S1007 同步及结果页本地快照是否出现倒退或覆盖。
2. 自动闯关成功后地图应按提交后的真实下一关刷新，保留完整挂机快照的精灵池、道具池、累计时间、次数及地图领奖记录；回执重放不额外扣费、发奖或推进。
3. 覆盖门槛前一关、完成门槛关、跨多图门槛、退出结果页后打开地图、同一次登录再次跳关、强停重登。单独记录地图是否可选、是否能实际进入及重启恢复情况。
4. 旧存档若数据库已正确推进，仅修复同步或刷新，不重置进度或重复发放历史通关奖励。数据库未推进时须以真实结算回执和任务代码证据追查，不能依据截图推测补关。
5. 当前已查明下节的底包配置矛盾，可据此修复；设备上“自动闯关后解锁异常”的其余表现继续按上述路径定位，不把配置修复直接写成全部物理机回归通过。

## 补充取证：43—46 图可领奖时仍被锁定

对固定底包 `app包/origin/origin.apk` 的 `lua32_database_map_proto.lua.bytes`、`lua64_database_map_proto.lua.bytes` 及两套 `copy_proto` 做只读解码，按全部关卡 `mapget` 归组，双架构结果完全一致：

| 地图 | copy_proto.mapget 实际关卡区间 | 原 map_proto.needlevel | 原 rewardlevel | 本地修正后 needlevel |
| --- | --- | --- | --- | --- |
| 41 | 15150—15430 | 15150 | 15430 | 保留15150 |
| 42 | 15431—16369 | 15430 | 15730 | 保留15430 |
| 43 | 16370—17308 | 16370 | 16030 | 16030 |
| 44 | 17309—18247 | 17310 | 16330 | 16330 |
| 45 | 18248—19186 | 18250 | 16630 | 16630 |
| 46 | 19187—19999 | 19190 | 16930 | 16930 |
| 47 | 20000—21999 | 20000 | 22000 | 保留20000 |

以上均为内部关卡编号，展示时减10000。其他可作对照的38—40、47—49图，其 `rewardlevel` 都等于下一张地图的 `needlevel`；42—46图奖励值仍每图增加300，而关卡分配约为940关。43—46图奖励门槛低于自身进入门槛，是已确认的配置矛盾，会出现用户进一步明确的“带红点的锁图进不去”。`fly_proto` 确认70043为雪地营地、70044为旷野地带。上述提取数据证明原表不一致，但不能单凭表间关系断言底包原设计应降低解锁还是提高奖励门槛；本次采用下述本地兼容规则。

### 本次消除矛盾的方案

1. 对用户明确的“带红点的锁图进不去”，采用保留旧存档奖励资格的本地修正：仅43—46四张原进入门槛高于自身奖励门槛的地图，最迟在取得自身奖励资格时开放，即 `needlevel` 取自身原 `rewardlevel`。这是本地兼容行为，不能表述为恢复了底包原始门槛。
2. 保留全部 `rewardlevel`、奖励种类与数量、通关收益、支付、`needworld` 训练师阶段和其他地图进入条件。42图虽与关卡分配存在长度差异，但不存在自身领奖门槛低于进入门槛的问题，本次不调整。
3. 同步修改两个 ABI 随包 `map_proto.needlevel` 和 Java `HangupMap.requiredMission` 对应四个值（表格最后一列），原 `allmaps_view` 比较规则保持不变。页面锁态、实际传送许可和重新登录后结果必须一致，不能只去掉锁图视觉。
4. 不删除或清零已领记录，不回收已到账资产，不补发旧图奖励，不强行挪动当前挂机场景或推进玩家进度。旧档已经领取的地图重新开放后也不能重复领奖。
5. 原 `copy_proto.mapget` 分配保留，不改变关卡怪物、掉落或数值；本地提前开放挂机场景不代表把普通冒险关卡重新分配给该图。自动闯关继续按原关卡表推进。

### 生效与验证要求

- 固定底包哈希、两套表的四行进入门槛、Java四个对应值、APK内资源及清单索引一致后才可随新版生效。核实所有奖励门槛、其他进入门槛及原关卡分配保持原值；不可仅改未被打包读取的文件。
- 隔离存档覆盖43—46图每个进入门槛前一关、完成门槛关、同次自动闯关跨门槛、重复领奖、旧已领回执、新版重启恢复，阶段条件未满足时仍不可进入。
- 物理机按用户原流程连续自动闯关并打开地图：真实关卡推进、地图进入许可、奖励可领状态保持一致。当前6662关且训练师阶段满足时，43、44、45图可进入，46图仍锁；原未领者保持原首通奖励资格，已领者保持已领状态。
- 本节属于设计与配置证据；实际编译、打包、设备回归状态由主智能体另记，不在本设计记录中虚构通过。
