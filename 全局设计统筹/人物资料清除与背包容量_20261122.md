# 人物资料清除与背包容量

- 版本：profile-cleanup-20261122，适用于 App 纯离线人物资料页及新增 `C10994 local_profile_clear`；10993 已由贴纸补给占用，本入口使用独立编号。
- 来源：用户本次明确要求；原 `playerinfo_view` 的 `Btns/Gifts` 为礼包兑换按钮；现有 `equipment_rating_entry` 补丁已提供资料页动态按钮模板。
- 容量数值：精灵背包最大值 500、人物背包最大值 600；由数值方向核对运行口径和已有扩容兼容性，不在本设计另行演算。

## 入口和事务

在礼包兑换右侧按顺序增加「清除所有精灵」「清除背包物品」「清除邮箱」。每项操作明确说明删除范围并确认一次，确认后生成本次操作唯一 `requestId`；同次重试继续使用原编号。请求只携带 `kind`、`requestId`，角色由当前已验证会话定位，不接受界面传入其他角色编号。

`ProfileCleanupService.clear` 在统一角色事务中执行，先锁角色，再以角色加 `requestId` 查验持久化回执。相同请求和类型返回已成功；相同请求换类型拒绝；无效类型或空编号拒绝。记录清除回执与资产写入处于同一事务，解析关联存档失败时整体回滚。成功后关闭人物资料页并重进当前角色，重新取得所有权威快照，不自动发放初始精灵。

## 清除范围

| kind | 操作 | 本地处理 |
| --- | --- | --- |
| 1 | 清除所有精灵 | 删除当前角色全部 `local_elf`，包括初始、已上阵、锁定、助阵、跟随、派遣及饲育寄存个体；解除道馆、助阵、跟随、旅行、火箭队占用及副本精灵生命记录；删除随精灵装备的力石、携带物和奥义石及其待确认洗练。饲育仅解除精灵配对，保留已产生的宠物和蛋。取消未结算战斗快照，保留历史图鉴、通关、领奖及次数。 |
| 2 | 清除背包物品 | 删除普通物品堆叠、精灵碎片、贴纸库存，以及未穿戴的训练家装备、力石、携带物和奥义石；包含锁定背包物品。保留已穿戴装备和刻印、角色钱包及货币账本；删除相应洗练预览和旧装备迁移源，防止重启补回。 |
| 3 | 清除邮箱 | 丢弃所有已读/未读邮件及未领取附件，不发放其中资产。清除附件并将主表置为已读、已处理、过期，保留邮件 ID 及正文作为历史寄送去重证据。邮箱列表和角标过滤过期邮件，重登后为空；订单、发奖、领取回执保持不变，防止触发旧奖励补寄。 |

未结算战斗取消覆盖主线、道馆、竞技共享 `attempt`、地下城、火箭队、巢穴、秘境、塔、异空间、伊甸园、每日副本、橘子群岛及旅行。不会退还已消耗次数或材料，不结算退出奖励。已有联赛报名使用原设计冻结快照并保留历史赛程，不重置赛季和领奖历史。

## 验收与生效条件

验证同一请求两次提交之间新获资产不会被第二次删除；跨角色操作互不影响；无效类型不写回执；null/损坏关联存档回滚。分别覆盖带装备精灵、已穿戴与未穿戴装备、未领取邮件附件、已有寄送回执和空背包空邮箱；重启后保持已清除状态，重新获取资产后可正常使用玩法。容量按原 500/600 最大值进行边界检查。

已完成现有表结构与调用关系静态核对。2026-11-22 使用 `.tools/qa-device.db` 只读备份到内存并开启 SQLite 外键检查，执行从 Java 源码提取的变更 SQL，24 项检查通过：目标资产和关联清理、钱包及其他角色保留、强制失败与 null JSON 回滚、冻结战斗取消、邮箱墓碑、旧装备迁移不补回及重试分支。JSON 和重试逻辑由 Python 镜像执行，未执行 Java 服务方法；`PRAGMA foreign_key_check` 无异常，报告在 `.tools/profile-cleanup-sqlite-result.json`。实际编译、设备界面及 APK 结果由本次实施记录和 `app包/版本迭代_app.md` 记录；本设计文档不代表设备界面回归已通过。
