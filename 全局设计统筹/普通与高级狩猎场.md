# 普通与高级狩猎场（C3101–C3105、S751）

2026-11-19 设计补证，适用于爱趣版 1.1（versionCode 3）。本页补充《App本地玩法设计与对接》的狩猎条目。以下协议与客户端行为已对照固定底包提取物；结算参数以数值统筹审定并随包加载的版本为生效条件。活动 10034 已明确隐藏，不开放第三场。

## 页面、动作与存档

| 动作 | 底包依据与本地行为 |
| --- | --- |
| C3101 查询 | 按角色、业务日和场别保存六个格位对应的模板。返回 `low`（普通场）、`mid`（界面称高级场）。同一业务日重复查询读同一池。底包 `hunt_view` 将 `high` 用作活动场，原字段与界面名称须按场序映射。 |
| C3102 进入 | 用角色真实 VIP 校验 `vip_proto.shol`，普通场 VIP0、高级场 VIP3。原入口展示对应券数和每次 1 张。原 guide_data 第 2707 步以 guide 打开入口，第 2710 步 GUIDE_HUNT_1 指定 itype=1，第 2717 步 GUIDE_HUNT_3 投 21015。普通场接受原任务引导的 guide=1，沿用正常扣券和同场恢复；高级场和活动场不接受该引导标记。引导第 2731 步锁定输入，等待成功入场后的 HUNT_READY。入场耗费、出场目标与 S751 的 `cur_elf/grid/lucky` 一起保存。普通重连恢复已经付费的场次。 |
| C3103 离开 | 结束本次场景会话，保留本日两场精灵池和已完成的交易。原帮助只明确凌晨清空池和幸运值，换目标及退场后幸运值的继承范围须在结算配置中表达。 |
| C3105 换一个 | 按当前场别优先消耗 21036 或 21037 一张。两场 `variable_proto[2107/2108].data6` 都为 `[104,0,300]`；`hunt_scene_view` 与 `zh_hunt[22]` 有无券时的货币确认。确认后每次换目标扣 300 钻石，取消或余额不足时保留原目标。首次入场另有资产不足文案 100334，刷新为 100339；无券首次入场的确认链须单独验收。C3105 无请求参数，当前角色和当前场次由本地服务确定。 |
| C3104 投球 | `itemid` 只接受 `variable_proto[2111]` 的三种球，校验库存及有效目标。成功返回 `errno=0/elfid/gridid`，入库本次捕获实例并清除当前目标；满包按已有邮箱溢出设计。正常捕捉失败对应文案 100337，保留目标并返回 `lucky`。原 `hunt_model` 仅在失败分支读取可选的 `chip_id/chip_num`，原页面按 `jinglingsuipian_proto` 查名。无碎片时省略字段，Lua 会把数值 0 当真。 |

## 捕捉、刷新与待审数值

- `overview_proto[2].txt → word1_proto[5003]`、道具说明 420074–420076 共同证实普通球只给 A 及以下增加幸运，高级球只给 S+ 及以下增加幸运，大师球必抓。幸运满时必抓当前精灵并清空。`hunt_scene_view` 以 `variable_proto[2293].data6[精灵.assess]` 作幸运条分母，缺档取末项。该显示逻辑没有给出阈值以下的成功概率。
- `hunting_proto` 的 `elfpool` 为模板与权重交替排列。普通场 10002、10003 的权重各合计 9862，高级场 20005 合计 11666。数值统筹须按每行实际权重总和演算。另有每格单独的 `grid_power`，及 2104/2105 中关于第六格的强制与排除次数。请明确计数对象、开始与重置时点、强制格优先级；本次底包客户端没有展示 `grid_power` 参与投球增量的计算。
- 普通球 `number1=2`、`number4` 前五对均为 6/10；高级球为 12、前八对均为 40/60，其余成对为零。大师球为 100000、所有对均为零。请数值统筹确认概率分母、区间取值方法、幸运累加与满值判定先后，并分别给出各档期望耗球量。变量 2112 指定蓝、紫品质的特殊处理，但未写明触发结果。成功分支没有碎片显示，失败分支也没有掉落算法。没有已确认来源的精灵碎片不在项目默认奖励范围内；数值方案需明确失败是否发放及其依据，不能据显示字段增加掉落。
- 2110 列出周一至周日凌晨 4 点，`zh_hunt[4]` 写每天 0 点，帮助 5003 仅写凌晨。建议本地普通、高级场统一采用北京时间 04:00 的配置边界，同时更新入口提示。数值统筹确认周期后，跨界首次访问原子轮换每日池并清空幸运值，相关回执继续按原业务日核对。

## 验收条件

按原入口核验 VIP0/VIP3、引导一次性领取、付券及无券确认、无券取消、余额不足、连续合法投球、满幸运、满包邮件、失败有无碎片的客户端分支。扣费、库存/邮件、当前目标、幸运值和回执在同一角色事务落盘。C3104/C3105 没有业务流水号，需在本地传输层区分同一请求重放与玩家连续点击。验证断网杀进程恢复、同日重查、跨刷新边界清空和活动场直调拒绝。本页完成配置、Lua 和协议静态核验，APK 接入、安装和页面实测由实施阶段记录。

## 2026-11-19 原客户端错误提示

设备无票进场曾显示“操作失败:100334”。两种 ABI 的 `languages_zh/errno.lua` 均以 250212 显示“狩猎券不足”。上文的 100334、100337、100339 属于 `word1_proto` 的文字编号。网关现以原错误码返回无票 250212、VIP 不足 250209、活动场关闭 250211、精灵球不足 250204、合法投球失败 250205、缺少刷新钻石 100006。正常失败仍回传幸运值，并刷新扣球后的背包。四次隔离启服验证无券、VIP、活动场、钻石余额不足、换目标重放、满包捕获、邮件以及跨日恢复。MuMu 断网已复验入口显示凌晨 4 点刷新，无票点击场地提示“狩猎券不足”。

### 两种门券的原主线来源

主线任务 10032「通关第16关」在前一项「累计强化6次装备」领取后出现。按底包 `mission_proto[10032]`，完成并领取发放普通狩猎券 21036 与普通球 21014 各 5、高级狩猎券 21037 与高级球 21015 各 1、钻石 200。领取后从冒险 → 日常 → 狩猎选择场地；高级场另需 VIP3。任务属于一次性产出。

两张券的 `item_proto.way=[1093,1024]` 和 `word1_proto[407020,407006]` 显示「秘境任务」「神秘商城」。当前底包的 `normal_shop_proto`、`mysterious_shop_proto` 实际商品行均未列出两张券，本地按确认的主线奖励入库。另有原主线 10098、10118 各奖励普通券 5 张，本轮任务目录仅接至 10032。
