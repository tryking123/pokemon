## 发物品与超级返利

发物品界面读取 `apk-entries/assets/pokemon-local/catalog/grant-mail-items.json`；离线业务 `ProfileMailService` 读取 `offline/resources/catalog/grant-mail-items.json`。两个目录仅加入可发放的真·百变怪 64190、小软 64189，类型为精灵附件 `2`。三个百分比模板不单独暴露。

发物品仍经过账号与角色归属校验、请求 UUID 去重、系统邮件创建和原邮箱领取。精灵背包满时按现有部分领取逻辑保留未领附件；不在发送邮件时绕过邮箱直接生成实例。重复发送同一请求和重复领取不能新增副本。

超级返利为活动 10026，原协议 C174 查询、C175 签到、C176 兑换。货架配置为 `offline/resources/activity/score-exchange.json`。新两档只能在现有 `rebate` 数组尾部追加，不能插入、重排或改写旧档位：兑换行为以一基档位索引落盘，重排会改变历史扣分解释。保留原活动周期、签到、实际已确认订单计分、背包容量检查、事务和请求去重。费用、次数和数量引用数值负责人本次交接。

## 形态、特性与存档

`charactername` 是展示文字引用：源 word1[424184] 为“重组”，[424185] 为“群聚变形”；源 `battle_unit.lua` 将其赋给 `ui.signal_name.text`。可执行特性来自 `jingling.character`，真·百变怪根为 104100，小软根为 105100–105900。它们位于 `character2_proto`，不是文本 ID。

三个百分比形态源表没有 `character`。原源战斗变形 helper 只替换 fighter 的 `sprite`、属性类型、性别和技能栏，保留原 fighter 的 `sid`、触发器与存档身份，因此小软在战斗内继续持有原根特性。不得为临时形态创建永久背包精灵，也不能把 424185 当作战斗触发编号。

迁移须闭包核对 `jingling`、`skill`、`character`、`character2`、`ditto`、对应文字、依赖特效与实际加载资源。`ditto_proto` 的变形目标引用要指向已迁入的内部形态；源引用旧冲突 ID 的位置按语义映射，不全局替换任意相同数字。

## 新增称号与皮肤

用户后续明确要求将全部对比包缺失的称号、皮肤去重导入，新旧账号均默认拥有并获得属性。以底包 ID 和旧存档为保留集合，缺失内容按稳定目录补入；同名异内容由数值和来源核对决定，不单凭名称覆盖。称号/时装默认拥有状态从当前有效 catalog 派生，旧档无需伪造购买历史。

持有属性每个有效 ID 累计一次；佩戴只改变展示，反复进入界面、换装、重登、升级不重复叠加。原 ID、已拥有、已选择的称号和时装记录保持有效。资源图片、动画、图标及文本仍需按实际加载路径迁入，不能只补目录数字行。

## 动画实际加载路径的最终取证

原包和喵星联盟的 `module/battle/battle_unit.lua.bytes`、`manager/res_mgr.lua.bytes` 逐字节相同。战斗角色初始化原型1读取 `jingling_proto[sid].ziyuan2`，按方向选择 PKM1 或 PKM2，然后调用 `res_mgr.load_anim(group,ziyuan2,parent)`；变身重载原型45使用相同字段和两组。两处都不读取 `ziyuan1` 或 PKM0。原背包 `elf_render` 原型2也使用 `load_anim(PKM1,base.ziyuan2,...)`。

`res_mgr.load_anim` 原型3调用 `asseturi.get_anim(group,id)` 后交给 Asset.LoadAsset。用真实原包 `helper/asseturi.lua.bytes` 在64位 LuaJIT执行得到：

- 真·百变怪战斗两方向分别加载 `Animations/PKM1/69282.prefab` 和 `Animations/PKM2/69282.prefab`，原包两个 prefab 及其完整16帧已解析到。
- 不会在战斗或背包详情流程请求不存在的 `Animations/PKM0/79282.prefab`；79282头像资源存在。不能因其没有PKM0动画就判定战斗缺图。
- 皮肤 `res_mgr.load_chrdata(sourse)` 原型6固定使用 Character 组，获取 CharacterData。`item_render` 的时装和碎片原型27/28直接传入 dress/dresschip.sourse；`scene_chr_pool` 原型9/14读取角色外观资源并交给同一方法。40097–40105实际路径均为 `Animations/Character/<编号>.prefab`，原包每项有完整 CharacterData（hCount=4、vCount=4、16帧）。

边界：原 `scene_chr_pool` 原型27的地图跟随精灵流程确实调用 `load_pkmdata(jingling.ziyuan1)`；后者固定走PKM0，没有自动转PKM1/2的fallback。源真·百变怪没有 follow 开放字段，保持其源规则即可；如果后续另行允许该精灵跟随，需先补79282的PKM0 CharacterData，不能拿战斗路径结论替代跟随功能验收。本次没有为此改动正在构建的APK资源。

像素与结构证据保存在临时 `pokemon-miao-migration-20261122` 目录的 `load-path-bytecode-proof.txt`、`resolved-loader-paths.json`、`semantic-resource-comparison.json` 和 `semantic-pixel-metrics.json`。共核对293个Sprite和23个prefab，0读取/指针解析错误。23个prefab的动作帧序和脚本参数一致；没有独立AnimationClip依赖，动画由CharacterData或UISpriteAnimation驱动。差异为Unity新版Image默认字段、脚本PropertiesHash及图集编码像素量化。

35个Sprite RGBA逐像素相同，214个alpha逐像素相同；剩余色值不完全相同，最大单Sprite可见RGB平均差6.50/255。原包为SpriteAtlas ETC2，源部分皮肤为独立RGBA32；最差帧目视仍为同一素材。可复用既有形象/帧动画，但不得宣称与供体逐像素相同。小软69414及79414各16个动作帧实际RGBA精确一致。若要求供体解码像素完全不变，则须另行克隆到独立Sprite/图集编号。

上述路径是实际原字节码取证，特性触发仍仅完成64位Lua隔离执行；没有据此宣称设备完整战斗已经通过。
