# 精灵进化与突破参数错误修复（2026-11-20）

适用：用户本次追加的“每只精灵进化均报参数错误”和 Lv60 阿罗拉臭臭泥突破注入报错。原 BUG3 物品扩围继续保留，二者不互相替代。固定底包 SHA-256 `f010a675dcb9ccacf899a2954e7e497be7f04c3ea94214140fa3434c817a7c45`。

## 原始依据与已确认根因

- 截图见 `问题/附件/精灵进化-确认.png`、`问题/附件/精灵进化-参数错误.png`。43006 阿罗拉臭臭泥 Lv60 从 +0 到 +1，原 UI 展示 140万金币、超进化石30、毒之石25、恶之石25，进度0/7，未勾钻补，点击确定报“参数错误”。
- 原 `sprite_utils` 进阶配置选择逻辑：当前 jinhua 行 `changeid[1] == 0` 且存在编号乘十的扩展行时，使用该扩展行。旧本地训练导出删去了十万以上的扩展行，导致终形精灵使用错误的阶段上限和消耗。430060 原表为7阶，首阶正是截图140万/30/25/25；43006基础行为5阶/80万，不能代替扩展行。
- C3007 为增加一阶；等级与亲密门槛属于 C3006 真正变形的终点条件。服务端曾将两者合并在共同校验处，导致未达到变形亲密门槛的精灵无法完成任意中间进阶。使用亲密1精灵可稳定重现旧服务拒绝。
- C270 为 `target,fodder`，C271 为 `uid,list,card,num`。原突破 `break1.inject = 2` 表示蓝色品质，不是需要2只材料。普通注入允许非同种指定品质精灵。旧服务误读并限制同种，且 C270 未应用原 `lighten` 费用。

## 已实现协议与存档

- `ElfTrainingService.train` C3007 按当前阶数读取正确 growth 消耗、增加一阶；C3006 仍校验原 jinhua 目标、等级、亲密和阶段上限，不允许任意指定新种类。最终变形目标采用原 jinhua.changeid，避免误用个别不一致的 jingling.changeid。
- 随包 `elf/training.json#growth` 完整保留919条原 jinhua 记录，包括终形扩展；所有消耗、门槛和上限引用原表，不新增数值。
- 新进阶将本次真实费用写入 `training.advanceCosts[step]`。`ElfRebirthService` 优先按该记录退还实际材料；没有记录的历史进阶按原基础表回退，避免把历史低费用进阶放大退款。重生清除进阶记录。
- C270/C271 普通步为一只原 inject 品质精灵，或 C271 对应品质突破卡；每11步的里程碑按原 starsprint 同种材料、awakening 门槛和 consume 数量核验。所有材料同时检查归属、重复、锁定、上阵及其他占用。
- C270/C271 均按原 lighten 扣费。概率使用原 successrate、variable3808属性交集加成、variable3809主向性差值曲线；失败仍是一次付费注入，不强制100%成功。
- C270/C271/C3006/C3007 使用连接与session组成的请求回执，事务内保存 `local_elf_growth_receipt`。同回执同参数返回原结果；不同参数拒绝；成功结算只扣一次。材料和金币不足不保存成长或消耗材料。
