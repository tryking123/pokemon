# 七日目标断连与本地入口核查

- 日期：2026-11-22（北京时间）。
- 适用：活动 10027、C177/C178，以及共用 `offline-network.lua` 的游戏协议入口。
- 来源：现有《App本地玩法设计与对接》、App 离线业务源码、`pokemon-local-20261122-pet-combat.apk` 内 64 位 Lua 字节码。
- 本次只修正本地执行与错误语义，沿用随包 `activity/carnival.json` 的奖励、进度与周期，不新增奖励或调整数量。

## 七日目标协议与存档

1. C177 读取当前活动轮次，返回 `errno/list/openday`。每一天的列表保留展示顺序。
2. 原页面点击领取时发送 C178：`idx1` 为日序，`idx2` 为当日列表一基行号；不是按分页后顺序重新编号。
3. 本地领取需校验打开面板的轮次、当日解锁、真实进度及已领记录。角色锁、发放与回执置于同一 SQLite 事务。跨轮旧页面和重复领取按原错误码返回，不发生奖励写入。
4. 成功响应含 `errno/idx1/idx2`。随后按既有实现推 S14 奖励、必要的余额、完整背包和邮件数量；消息只有事务提交后才能交付 Unity。
5. 原 `fesrevel_model` 把 C178 响应直接广播给控制器；控制器按 `idx1/idx2` 标记列表已领，然后调用 `finish_get`。`finish_get` 再触发 C177 刷新。该链没有依赖回调第三参数或原请求缓存。

## 已确认的共性问题

旧 `offline-network.lua` 对 `poll` 和整批 `Network.OnMessage` 使用同一个 `pcall`。任意页面回调、奖励展示或消息分派异常都会把本地 `connected` 置为 `false`，并调用原网络 `Network.OnException()`。后续帧也会停止处理。因此，“网络异常，连接已经断开”不能证明请求仍在连接远端；本地 UI 异常也会被转换为同一提示。

这项风险覆盖共用桥接层的所有入口，不能只修改七日按钮或隐藏提示文字。应将本地业务调用、单帧回调失败与会话退出分别处理；一帧回调失败不能丢弃同批后续帧，也不能自动重放已经提交的领取或购买。明确退出仍按退出语义关闭会话。

64 位 S14 原处理器已复核：`adds.items` 按物品数据处理，`adds.elschips` 按 `id/n` 处理；奖励提示根据原配置显示。现有七日返回字段与原协议一致，尚未从静态字段检查确认七日特有的 Lua 错误点。迟到响应访问已销毁页面等情况仍须结合设备日志辨别，不把推测写成已复现根因。

## 本地入口扫描边界

已查 `offline/src/`、Android `src/` 和 `embedded/src/` 的 Socket、ServerSocket、HttpURLConnection、OkHttp、远端 URL 和回环地址引用。未找到这些运行源码主动创建 HTTP/TCP 连接的实现。`OfflineAppApi` 中的 `127.0.0.1` 是兼容下单业务的进程内来源参数；`GamePaymentServiceImpl` 对它进行旧接口校验，并不创建回环监听。原协议消息继续由 JNI → OfflineBridge → OfflineGameSession 进程内分派。

此项是源码静态扫描结论，不代表全部原 APK SDK 或全部玩法均已设备验收。未实现接口沿用待实现清单，不能通过吞掉异常或返回虚假成功宣布已接入。

### 原 Unity 字节码的补充扫描

64 位资源中的 `WWW` 字符串不能仅按命中数判断网络残留。实际指令复核结果如下：

| 模块 | 实际执行情况 | 本地替代要求 |
| --- | --- | --- |
| `login_model` | 第 12、13 个函数已被替换为六条指令，通过 `loadstring` 执行本地区服和历史角色查询；`WWW` 仅残留在未清理的常量池。 | 保留现有 `/realmlist`、`/get_my_plyer` 进程内调用。 |
| `newlogin_model` | 第 12、13 个函数仍真实调用 `WWW` 和 `coroutine.www`；公开 `load` 的执行链会调用它们，属于可执行的旧网络入口。 | 使用与 `login_model` 相同的两个本地替代函数，维持原回调。 |
| `notice_model` | 第 2 个函数为公开 `load_notice` 的函数体；缓存为空时真实调用 `WWW`。 | 从进程内 `/notice.txt` 获取文本，再广播 `set_notice`。本地服务已有该路由；再次打开也不允许回退旧网络。 |

这三个模块需分别核对 32/64 位构建产物与实际调用，不能仅修改脚本而未核对最终包。上述结论基于修改前已产出 APK 的 64 位指令检查，最终修复和故障注入结果另见交付验证记录。

## 验收要求

- 无网络、无 PC 服务、无 ADB reverse 时，C177 能打开七日列表；已达标且已解锁档位可领，奖励真实到账。
- 同档再次领取、未达标、未解锁、跨轮旧页面均不重复发放；重新进入页面与重启后已领标志保持。
- 连续领取物品、钻石和碎片档；普通背包满时按既有邮件兜底处理。
- 向某一帧回调注入异常，后续背包、余额与邮件帧仍派发；后续请求可继续本地执行，不触发原断连弹窗，不自动重放写操作。
- 原响应回调链 C178 → C177、页面关闭后的迟到响应、主动退出后重新登录分别验证。
- App 独立构建不读取服务端模块；最终 APK 完成签名、16 KB 对齐及补丁条目核对。
