# 道馆退出与脱离卡图

适用版本：2026-11-22 本地离线修复方案 v1。适用范围：道馆异常退出后重新入服、个人资料页主动脱离卡图。来源：用户连接 Xiaomi 13 Ultra 后报告的道馆页面永久滞留，以及资料页「发物品」上方新增按钮要求。

## 当前依据

- `app端代码/local-patch/patch-unity-arena.py` 在个人资料的 `Btns` 容器注入「发物品」与「重进角色」；新增按钮复用现有按钮皮肤及字体。
- `GameGatewayService.enterScene` 从角色持久化位置生成首张场景；中断战斗处理在 `ready` 后执行。只清理战斗而保持道馆位置，不能保证从异常地图中恢复。
- `DisconnectedBattleService.settle` 已汇总各本地玩法的撤退业务。`DojoCombatService.flee` 当前依赖有效场景与 1800 秒战斗时限，过期或位置不一致的残留记录需要专门清理，不能只依赖 `active` 判断。
- `SceneService.CITY` 为主城 71002，既有常用回城落点为格点 (26,33)，持久化坐标为 (832,1056)。场景推送使用原 S4；S20 仅校正位置，不能替代完整切图。

## 业务流程

1. 在个人资料「发物品」正上方显示「脱离卡图」。点击立即关闭资料面板并请求本地恢复，不增加确认弹窗。
2. 请求通过现有进程内协议桥进入 App 业务层，由已认证会话识别当前角色。请求不允许指定其他角色、地图、坐标或奖励。
3. 在角色事务内结束尚未结算的当前战斗，沿用原玩法撤退语义；失效、过期的道馆尝试也应删除。不存在尝试时保持成功，连续点击不重复计次。
4. 将角色位置保存为主城 71002 的 (832,1056)，清空旧副本返回场景和坐标。事务提交后刷新连接角色快照并推送完整主城场景，加载完成后同步角色位置及页面状态。
5. 道馆异常退出后重新入服，须在首张场景推送前清理中断尝试并恢复主城位置，避免首张图仍加载已坏的道馆现场。应以道馆实际配置识别总馆和分馆，不把正常其他玩法存档统一回城。

本次实施交接：资料按钮使用 `LocalEscapeMap`，布局中心 (235,405)、宽 116，置于「发物品」上方；点击关闭资料并发送原 C8 `mapJump`，`id=990001` 作为本地专用恢复动作。入口从认证连接取得角色，执行撤退和主城保存后发送 S4。`enterScene` 起始调用 `restoreScene`，先处理断线战斗，再对总馆 72001–72008、分馆 72101–72148 回城；`ready` 不再迟清理。`settle` 无条件调用道馆 `flee`，后者只要有残留尝试便删除，正式挑战只计一次失败，不再受场景和 TTL 限制。

脱离动作不产生胜利、不补发通关奖励、不增加历史通关、不清空已验证击败进度和阵容；保留账号、角色、资产、已结算奖励与其他永久存档。原规则已消耗的机会不退回；正式挑战撤退按既有失败规则处理一次。热身沿用其原计次规则。失败应回滚，不能先向 Unity 报告回城成功。

## 实施约束

业务和事务放在 App 的 `offline/src` 业务层；Android 页面及协议入口只负责转交和应答。构建及运行不依赖服务端目录、不增加网络端口、不通过清除数据或卸载重装修复。实机升级沿用现有签名链，并保留原数据库。

## 验收

| 场景 | 应有结果 |
| --- | --- |
| 当前卡在道馆页面的旧存档升级后冷启动 | 能进入主城，原角色及资产保留 |
| 正式道馆挑战中断后重登 | 首张场景为主城，尝试结束且失败仅计一次，已通关和已击败进度保留 |
| 道馆尝试超过 1800 秒、或尝试与存档场景不一致 | 可清理残留并回城，不形成永久互斥 |
| 道馆总馆、分馆、其他地图点击脱离卡图 | 资料关闭，主城完成切图且可移动、可再进入玩法 |
| 连续点击、回城后再次点击、重启 | 不重复发奖或重复结算，仍在主城正常落点 |
| 按钮布局 | 位于「发物品」正上方，文字完整、点击区域不覆盖其他功能 |
| 断外网、无 PC 服务、无 ADB 反向转发 | 上述恢复仍可完成 |

校验状态：App编译、无服务端目录独立构建、APK签名、16KiB对齐和条目摘要通过。Xiaomi 13 Ultra保留数据覆盖升级，用户确认已离开卡住的道馆；资料按钮视觉和点击显示主城通过，原道馆入口及退出回城通过。过期尝试和其他玩法撤退未逐项在实机制造回归，详细范围及APK摘要见 `app包/版本迭代_app.md`。
