# 战斗属性快照查看

适用：App 纯离线 Unity 战斗页面；方案版本 `battle-inspect-20261124`。本次仅提供观察功能，不调整任何奖励、阵容、属性计算或战斗结算规则。

## 用户操作与生命周期

- 战斗页面增加“战斗属性”按钮，打开双方精灵属性面板；使用“上一只/下一只”按先我方后敌方的顺序查看精灵，显示名称、阵位、存活状态。使用“基础/当前”和“Buff/状态”切换内容，长内容通过“上一页/下一页”分页。
- 新战斗创建 Stage 并完成开场准备后，主动采集一次双方快照，包含开场特性和光环已经生效的结果。快照保存在该场战斗的内存中，不写 SQLite。
- 打开、关闭面板，切换精灵、内容或分页，只显示已有快照。回合推进、血量变动、Buff 增减均不触发读取，不增加周期轮询或每帧属性扫描。
- 面板明确提示“快照不会自动更新”，显示采集回合/序号。只有点击“刷新”才重新读取当前战斗双方属性与状态，整体替换快照。
- 缓存必须属于当前 Stage；连续下一关、重新开战、退出再进使用新 Stage 时清除旧快照并采集一次。相同战斗的页面显示切换不重复采集。不得仅以 `battle_view.start` 是否运行判断新战斗，因为已有页面重入曾沿用旧 Stage。
- 退出战斗或更换 Stage 时清除快照及旧场景引用，防止旧面板刷新上场战斗。关闭面板后仍保留本场快照。刷新过程中不写入战斗对象，不调用推进回合、触发器分派或奖励逻辑。

## 展示口径与字段来源

六维为生命上限、物攻、物防、特攻、特防、速度，真实键名分别为 `hp_max/physical_attack/physical_defense/special_attack/special_defense/speed`。另列当前生命、护盾、命中 `hit_chance`、闪避 `dodge_chance`、暴击 `crit_chance`、韧性 `toughness` 及原战斗引擎可读取的其他属性。基础值和当前生效值分别标明口径，不能把开战输入或 `actor.att[name].base` 标成实时生效值。

已核对代码依据：`local-team-talents.lua` 使用 `formation.interface()` 第三项 `stats`；其中 `stats.get(actor, property)` 已覆盖团队光环实际叠加算法。当前生效属性应沿用这个入口。原 `formation` 个体含 `att`、`buffs`、`hp`、`hp_shield`、`position`、`id`、`sid`；Buff 是按类别和实例组织的嵌套表，不应直接作为 UI 可变引用保存。

采集将可展示的标量复制为独立数据；Buff 使用 `buffs[kind].name` 及效果实例标量，包含可用的 `round/extra/ratio/prop`，免疫或特殊开关在状态内容中列出。未知原始键及原值保留，不编造中文规则。没有的数据标记“无/未提供”，不能伪造为有效的零属性。数值明确按引擎原值展示，不将闪避、韧性或所有 `ratio` 值统一冒充百分比。

### 006 槽位转换落点与来源冻结实现

最终交付包为 `006`：`005` 候选只包含恢复及展示，不含槽位转换，不作为最终交付。实现为“Java 冻结并逐槽换算、Unity 建立前排副本时一次叠入”，保持个人基数冻结在先、槽位转换在特性之前的顺序。

`AssistBattleService.snapshot` 按原槽位条件生成协议字段 `assist_slot_type:112`、`assist_slot_percent:113`、`assist_slot_value:114`。逐槽贡献为 `floor(独立助战自身对应属性 × 已激活整数百分比 / 100)`，先逐槽取整再汇总；配置及百分比由数值负责人按原 `cheer/stage_manager` 核对。原 Lua 1536 个槽位用例及目标 Android 真实 Java 算法的 768 个有占位用例逐项比对均通过；空槽由原 Lua 与 Mapper 排除逻辑覆盖。

Unity `formation.new` 在原构造前调用 `withSlotBonuses`，复制本场 `data.pokemon` 与各前排成员的顶层表，仅给副本六维加各槽转换总量，再交原 `stats.load`。输入原成员及 `data.assists` 不改写；同 UID 出战与助战、重复槽位、重复助战 UID 按原排除条件过滤，贡献来源保留于 `side.slotBaseBonuses`。全血输入随转换后的生命上限保持全血；非全血输入保留原生命，不能借新增面板或槽位转换洗满残血。重复构造应从同一未改写协议快照得到同一结果，不在旧 actor 上再次累加。

后排仍独立 `stats.load`，不接受前排槽位加成。UI 按“槽位固定贡献”“特性固定/比例与实际 Buff 来源”“后排源六维”分列，原生数值显示和交互验证见下节。
